# 未実装の機能とTODO

この文書では、現在の機能範囲に含まれない候補と、完了していない開発・検証作業を管理する
未実装の機能は対応の確約ではなく、利用要求とマルチバージョンでの保守負担を確認して採否を決める

## 未実装の機能

### コピー対象と形式

- [ ] コンテナ画面を開いていないとき、手に持っているアイテムをコピーする
  - 既存のキー操作との競合と、対象を選ぶ条件を先に決める
- [ ] EMIやREIなど、レシピビューアー独自の疑似スロットへ対応する
  - ModごとのAPI、対応Minecraft版、任意依存の分離方法を確認する
- [ ] アイテムID、個数、Lore、NBT、Data Componentをコピー形式として選べるようにする
  - Minecraft版によるデータ表現の差を版固有の処理へ閉じ込める

### 設定

- [ ] コピー用のキー割り当てを変更できるようにする
  - テキスト入力欄の通常のコピー操作を優先する契約を維持する
- [ ] コピー形式を選ぶ設定画面を追加する
  - 設定画面や設定ライブラリを実行時の必須依存にするかを先に判断する

## クライアントテスト基盤

- [ ] 再実行の判定を対象ごとの実行内容へ変更する
  - 対象のクラス、リソース、解決済み依存関係、Java、OS、入力ドライバー、テストシナリオを識別する
  - 文書、旧方式、無関係な対象の変更では、実行内容が変わらない対象の成功結果を破棄しない
  - テスト基盤と製品の変更による再確認を区別し、無効化理由を表示する
  - 根拠の足りない旧レポートを新方式の成功結果へ変換しない
- [ ] Reflectionの複数名フォールバックで、メソッド不存在と呼び出し先内部の失敗を区別する
- [ ] 起動時にフックの適用を確認し、差し替え失敗を最初の操作まで持ち越さない
- [ ] ビルド中や検証中にソースが変更された場合は結果を無効にする
- [ ] 入力ハッシュへ実行スクリプト、対象一覧の生成処理、起動設定を含める
- [ ] 強制終了に備え、クリップボードの復元とクライアントプロセスの所有権を管理する
- [ ] 配布Jarによる起動検証を、開発クラスパスによる検証とは別のモードで提供する
- [ ] 新しい互換境界を追加したとき、既存の代表版でフォーカスと入力動作の回帰を確認する

## 配布

- [ ] 検証済みのJarと`distribution/project.json`を使用し、ModrinthとCurseForgeへ公開する処理を実装する
- [ ] 公開前に、各Jarへ紐付けるMinecraft版とLoaderが配布マニフェストと一致することを検証する
- [ ] 一つの公開処理が失敗しても、別Loaderの公開へ誤った成果物を渡さない構成にする

## リリース前チェックリスト

配布するMinecraft版とLoaderの組み合わせごとに確認する

- [ ] タグ対象のコミットでGitHub Actionsのビルドとコアテストが成功している
- [ ] Node数と配布Jar数が一致し、各JarのMinecraft、Loader、必要Java、Mod版が配布設定と一致している
- [ ] 配布するすべてのMinecraft版とLoaderでクライアントが起動する
- [ ] サバイバルとクリエイティブのインベントリ、チェスト、作業台、かまど、金床でコピーできる
- [ ] 各Loaderで標準コンテナ画面を継承するMod画面を一つ確認している
- [ ] 空スロットで既存のクリップボードが維持される
- [ ] 通常名、カスタム名、日本語名、前後の空白が期待どおりにコピーされる
- [ ] 左Ctrlと右Ctrlで動作し、長押しでも成功通知は一回だけ表示される
- [ ] Ctrl以外の修飾キーとの組み合わせでは発火しない
- [ ] クリエイティブ検索、レシピブック検索、金床の入力欄で選択文字列をコピーできる
- [ ] 他Modが先に処理したキー入力を上書きしない
- [ ] コピーによってアイテム、スロット、コンテナの状態が変わらない
- [ ] シングルプレイと、サーバーにこのModを入れないマルチプレイ接続で動作する
- [ ] 未確認のMinecraft版を互換対象として登録していない
- [ ] `verification-manifest.json`の動作確認状態を実際の結果へ更新している
